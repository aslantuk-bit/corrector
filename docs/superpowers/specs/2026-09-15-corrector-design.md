# Корректор — проверка орфографии, пунктуации и стиля юридических текстов на русском и казахском

Дата: 15.09.2026. Статус: дизайн согласован с заказчиком, готов к плану реализации.

## 1. Цель

Переносная программа для Windows, которая проверяет документы Word (.docx) на русском и казахском языках: орфографию, пунктуацию, грамматику (для русского), типографику и формальную стилистику юридических текстов (судебные акты и подобные документы). Работает с флешки или из папки на компьютере без установки, без прав администратора и без интернета. Пользователи — сотрудники суда и других госорганов, работающие без автора программы рядом.

## 2. Условия эксплуатации

- Рабочие ПК на Windows 10/11 x64, обычные офисные машины без видеокарты. Прав администратора нет, интернета нет. Microsoft Word установлен.
- Программа лежит в одной папке (на флешке или скопирована на рабочий стол) и запускается двойным щелчком. Никаких установщиков, служб, записей в реестр.
- Разработка ведётся на Mac (Apple Silicon). Windows-машины у автора нет: сборка — на сборщике GitHub (Windows), проверка глазами — в виртуальной Windows 11 ARM через UTM на Mac, финальная проверка — на рабочих ПК коллег.

## 3. Рамки

Делаем:
- входные файлы — только .docx; текст, таблицы, колонтитулы;
- проверка орфографии и пунктуации (главное), грамматики русского, типографики, формальной стилистики уровня «правила» (повторы, длина предложений, разнобой имён и терминов, названия органов и законов, сокращения, даты, числа);
- окно с подсветкой и списком замечаний, принятие исправлений кнопками, сохранение копии, примечания Word на полях;
- словарь исключений и файл своих правил, которые коллеги правят в Блокноте и передают друг другу;
- режим командной строки для пакетной проверки и автотестов.

Не делаем:
- языковые модели (нейросети) — ни локальные, ни облачные; «глубокая» стилистика (канцелярит, порядок слов, переформулирование) вне рамок;
- редактирование текста руками в окне программы — правки вносятся принятием предложенных исправлений или в Word;
- сноски (python-docx их не поддерживает) — в первой версии не проверяются;
- старый формат .doc, pdf, вставка из буфера обмена;
- режим исправлений Word (track changes) — только примечания.

## 4. Архитектура

### 4.1 Компоненты и структура репозитория

Один пакет Python `corrector` с ясно разделёнными частями:

```
corrector/
  app/        окно (PySide6): главное окно, список замечаний, подсветка, фоновая проверка, справка
  core/       модель документа, токенизация, деление на предложения, определение языка, модель замечания,
              словарь исключений, настройки, журнал
  engines/    lt.py (клиент и запуск LanguageTool), ru_spell.py (запасная орфография spylls + ru_RU),
              kk_spell.py (spylls + hunspell-kk + юридический лексикон), kk_stem.py (стеммер kazsearch)
  rules/      движок правил, встроенные правила (общие, русские, казахские), загрузчик правила.yaml
  docx_io/    чтение .docx с картой фрагментов, замена внутри фрагментов, примечания, сохранение копии
  cli.py      командная строка
data/         словари, лексиконы, списки отключённых правил LanguageTool, эталонные названия органов и законов
docs/         спецификация, каталог правил (rules-ru.md, rules-kk.md), инструкция пользователя
tests/        модульные и интеграционные тесты, образцы .docx
tools/        скрипты только для Mac: выборка из corpus.db, прогон по корпусу, сборка лексикона
build/        спецификация PyInstaller, workflow GitHub Actions, список скачиваемых артефактов с контрольными суммами
```

Внешние части, лежащие рядом в поставке: `java/` (Temurin JRE 21), `languagetool/` (снимок LanguageTool), `data/`.

### 4.2 Путь документа

1. Открыть .docx → `DocumentModel`: список абзацев (тело, таблицы любой вложенности, колонтитулы). У абзаца — сквозной текст и карта фрагментов форматирования (run): для каждого run начало и конец в тексте абзаца. Гиперссылки и поля обходятся как обычные run.
2. Для каждого абзаца — язык (п. 4.4), токены с позициями, предложения.
3. Русские абзацы пачкой уходят в LanguageTool; казахские — в казахский словарь; все абзацы — в слой правил. Каждый движок возвращает список замечаний в координатах абзаца.
4. Слияние: отсев по словарю исключений и лексиконам, отсев отключённых правил, снятие дублей (одинаковый отрезок и категория — остаётся замечание нашего слоя, у него точнее сообщение), сортировка по положению в тексте.
5. Показ в окне. Принятие исправления меняет текст внутри нужного run (при необходимости run разрезается), позиции остальных замечаний того же абзаца сдвигаются.
6. Сохранение копии рядом с оригиналом; по желанию — примечания Word к оставшимся замечаниям.

Проверка идёт в фоновом потоке по абзацам с полосой прогресса и кнопкой «Отмена»; окно не замирает.

### 4.3 Модель замечания

`Issue`: идентификатор абзаца; начало и конец в тексте абзаца; категория (`spelling`, `punctuation`, `grammar`, `typography`, `style`); уровень (`error` — красный, `warning` — оранжевый, `hint` — синий); идентификатор правила; движок (`lt`, `ru_spell`, `kk_spell`, `rules`, `user`); сообщение по-русски; варианты замены (до пяти, по убыванию уверенности); контекст для показа. Категории в окне сгруппированы в четыре галочки: «Орфография», «Пунктуация и грамматика», «Типографика», «Стиль».

### 4.4 Определение языка

По абзацу: очки за казахские буквы (ә ғ қ ң ө ұ ү һ і) и частотные казахские служебные слова против очков за частотные русские служебные слова; при ничьей — язык предыдущего абзаца, для первого — русский. Внутри русского абзаца слова с казахскими буквами (имена, названия) проверяются казахским словарём. Внутри казахского абзаца слово, неизвестное казахскому словарю, но известное русскому, помечается подсказкой «русское слово в казахском тексте», а не орфографической ошибкой; внутри кавычек такие слова не помечаются вовсе (цитаты названий на русском).

## 5. Движки

### 5.1 Русский: LanguageTool

- Снимок LanguageTool (модель выпусков — ежедневные снимки; в сборке фиксируется снимок за конкретную дату с контрольной суммой) с модулем русского языка: орфография, 892 XML-правила и 20 Java-правил. Урезаем поставку до русского модуля, если сервер с одним модулем запускается и проходит тесты; иначе везём полный снимок.
- Запуск при старте программы: `java/bin/java.exe -Xmx768m -cp languagetool-server.jar org.languagetool.server.HTTPServer --port <свободный> --config lt.properties`, привязка только к 127.0.0.1. Готовность — ответ `/v2/languages` в течение 60 с; иначе движок помечается недоступным. При выходе процесс останавливается; файл `lt.pid` защищает от сирот при аварийном завершении.
- Клиент: `POST /v2/check`, `language=ru-RU`, `disabledRules` из `data/lt_disabled_rules.txt`. Абзацы отправляются пачками до 20 000 символов, разделитель — две пустые строки; смещения ответа переводятся в координаты абзацев.
- Категории LanguageTool отображаются на наши: `TYPOS` → орфография; `PUNCTUATION` → пунктуация; `GRAMMAR`, `AGREEMENT`, `CASING`, `CONFUSED_WORDS` → грамматика; `TYPOGRAPHY` → типографика; `STYLE`, `MISC` и прочие → стиль.
- Список отключённых правил составляется по прогону на корпусе (п. 14) и хранится в данных, не в коде.
- Ограничение запускателя Java на Windows (выяснено на этапе 0, JDK-8242283, adoptium-support #1066): `java.exe` не запускается из папки, в пути которой есть символы вне системной кодовой страницы ANSI («Error: could not find java.dll»). На русской Windows (cp1251) кириллица проходит, казахские буквы и любые не-ASCII символы на английской Windows — нет. Поэтому перед запуском проверяется, укладывается ли путь к `java/` в кодовую страницу (`GetACP`), а при отказе прямого запуска папка `java/` копируется в первую доступную папку без таких символов (`%PUBLIC%`, `%ProgramData%`, `%SystemDrive%\Temp`, `%TEMP%`) и Java запускается оттуда; повторные запуски используют готовую копию, если файл `release` совпадает. Если копия не удалась — жёлтая плашка и запасная орфография (п. 5.2).

### 5.2 Запасная русская орфография

Если LanguageTool недоступен — spylls со словарём ru_RU (из репозитория словарей LibreOffice). Даёт только орфографию с вариантами; пунктуация и грамматика русского в этом режиме отсутствуют, о чём сообщает жёлтая плашка.

### 5.3 Казахский: словарь и стеммер

- Орфография: spylls со словарём hunspell-kk v0.2.8 (131 289 основ, порождённый файл аффиксов с сингармонизмом и цепочками суффиксов). Перед словарём — проверка по множеству слов юридического лексикона `data/lexicon_kk_legal.txt` и по словарю исключений. Варианты замены — до пяти, с кэшем на время проверки (подсказка занимает 0,2–0,9 с на слово).
- Стеммер kazsearch (чистый Python) — для правил стиля: повторы по основе, разнобой терминов, сверка названий.
- Apertium-kaz используется только на Mac при сборке лексикона как эталон морфологии, в поставку не входит.

### 5.4 Слой правил

Правило — объект с идентификатором, языком (`ru`, `kk`, `any`), категорией, уровнем, сообщением и функцией поиска, которая получает абзац (текст, токены, предложения, язык) и возвращает замечания. Два вида правил:
- шаблонные — регулярное выражение плюс замена (в коде и в `правила.yaml` пользователя);
- программные — на Python, для проверок по всему документу (разнобой имён, единый формат дат, названия органов).

Каждое встроенное правило описано в `docs/rules-ru.md` или `docs/rules-kk.md` таблицей «неправильно → правильно → сообщение»; тесты читают эти таблицы и проверяют, что правило срабатывает на «неправильно», не срабатывает на «правильно» и предлагает указанную замену.

## 6. Каталог проверок

Общие для обоих языков (слой правил):
- смешанные алфавиты: латинская буква внутри кириллического слова и наоборот; римские числа, набранные казахской «І»;
- типографика: двойные пробелы, пробел перед знаком препинания, отсутствие пробела после, кавычки "…" вместо «…», дефис вместо тире между пробелами, «ст.5», «№5», «г.Астана», «2024г.», инициалы без пробела после фамилии, неразрывные пробелы в «ст. 5», «№ 5», разрядах чисел;
- числа и даты: единый формат дат в документе, разряды в суммах, слово «тенге» после суммы;
- повторы: слово дважды подряд; одно и то же знаменательное слово (по лемме или основе) в соседних предложениях;
- длинные предложения: длиннее порога (по умолчанию 60 слов) — подсказка;
- разнобой имён: похожие, но не одинаковые фамилии и названия организаций в одном документе (расстояние редактирования 1–2) — предупреждение;
- названия органов и законов: сверка с эталонным списком официальных названий на обоих языках (`data/names_ru.txt`, `data/names_kk.txt`); неверный регистр или буква — подсказка с правильной формой;
- правила пользователя из `правила.yaml`.

Русский: всё, что даёт LanguageTool (орфография с вариантами, запятые при союзах, оборотах и вводных словах, согласование, падежи после предлогов, паронимы, часть стилевых правил) минус список отключённых правил; плюс юридические шаблоны в нашем слое («в соответствие с», «согласно приказа», «в течении срока», оформление ссылок на статьи).

Казахский (наш слой, категория «пунктуация»): запятая перед противительными и причинными союзами (бірақ, алайда, дегенмен, әйтпесе, себебі, өйткені), после вводных слов (мысалы, әрине, демек, сонымен, біріншіден), при повторяющихся да/де, перед «деп» после цитаты; тире между подлежащим и сказуемым-существительным; слитное «-мен/-бен/-пен»; раздельные ма/ме/ба/бе/па/пе и да/де/та/те; дефис в числительных с аффиксами («5-ші», «2024-тен»); формат дат («2024 жылғы 5 қаңтардағы»). Категория «стиль»: термины по перечню Республиканской терминологической комиссии (termincom.kz) как подсказка «рекомендуемый термин».

Уровни: орфография, явная пунктуация и грамматика — ошибка; типографика и стиль — предупреждение; рекомендуемый термин, длинное предложение, русское слово в казахском тексте — подсказка.

## 7. Окно

- Одно окно PySide6, заголовок «Корректор <версия>».
- Сверху: «Открыть», «Проверить», «Сохранить копию», «Сохранить с примечаниями», «Справка»; четыре галочки категорий. Документ можно перетащить мышью в окно. После открытия проверка запускается сама.
- Слева: текст документа, только для чтения, подсветка трёх цветов; щелчок по подсветке выбирает замечание справа, выбор справа прокручивает текст.
- Справа: список замечаний в порядке текста. У каждого: категория, сообщение, фрагмент, кнопки с вариантами замены, поле «своё исправление» с кнопкой «Заменить», «Пропустить», «Добавить в словарь» (только для орфографии), «Больше не показывать это правило».
- Внизу: счётчики (ошибок / предупреждений / подсказок), полоса прогресса, состояние движков («LanguageTool готов» или жёлтая плашка «пунктуация русского недоступна: Java не запустилась»).
- «Справка» открывает окно с инструкцией (та же инструкция лежит в папке как `ИНСТРУКЦИЯ.txt`).
- При запуске — заставка «Запуск… с флешки первый старт может занять до минуты».

## 8. Работа с Word

- Чтение: python-docx 1.2; абзацы тела, таблиц (включая вложенные) и колонтитулов. Текст run читается со вставками табуляции и разрывов строк, чтобы позиции совпадали при записи.
- Замена: текст меняется внутри того run, где лежит фрагмент; если фрагмент пересекает границу run, run разрезается с копированием свойств (`w:rPr`). Форматирование абзаца и остальных run не трогается.
- Сохранение: «Сохранить копию» → `<имя>_проверено.docx` рядом с оригиналом; при занятом имени — `<имя>_проверено (2).docx` и далее. Оригинал не изменяется никогда.
- Примечания: «Сохранить с примечаниями» → та же копия плюс примечание Word (`document.add_comment`) к каждому замечанию, которое не принято и не пропущено: автор «Корректор», текст — категория, сообщение, варианты. Примечание привязывается к точному фрагменту через разрезание run. В колонтитулах примечания ставить нельзя — такие замечания остаются только в окне и в текстовом отчёте.
- После сохранения — кнопка «Открыть в Word» (`os.startfile`).

## 9. Файлы для коллег и настройки

Лежат рядом с программой; если папка защищена от записи — в `%LOCALAPPDATA%\Корректор\` (на Mac — `~/Library/Application Support/Корректор/`), и программа показывает путь в «Справке».

- `словарь.txt` — исключения: одно слово или фраза на строку, регистр не важен, строки с `#` — комментарии. Кнопка «Добавить в словарь» дописывает в конец. Действует на орфографию обоих языков и на разнобой имён.
- `правила.yaml` — правила пользователя: список записей с полями `id`, `язык` (`ru`/`kk`/`any`), `найти` (регулярное выражение; простое слово ищется по границам слова), `заменить` (необязательно), `сообщение`, `уровень` (`ошибка`/`предупреждение`/`подсказка`). В поставке — файл с примерами в комментариях. Ошибка в файле — предупреждение с номером строки, остальные правила работают.
- `настройки.json` — галочки категорий, отключённые правила, порог длины предложения, последняя папка. Кнопка «Сбросить настройки» в «Справке».

## 10. Командная строка

Второй исполняемый файл в той же папке, `Корректор-cli.exe` (консольный, общая папка `_internal` с окном):

```
Корректор-cli.exe --check <файл.docx|папка> [--out <папка>] [--comments] [--report]
```

Проверяет файл или все .docx в папке, кладёт копии с примечаниями (`--comments`) и текстовый отчёт (`--report`, по строке на замечание: файл, абзац, категория, фрагмент, сообщение, варианты). Код возврата 0 при успешной проверке независимо от числа замечаний, 2 при ошибке чтения файла. Используется для пакетной проверки и для проверки сборки на сборщике GitHub.

## 11. Отказы и защита

- Java не запускается, порт занят, сервер не ответил за 60 с — жёлтая плашка, русская орфография через spylls, всё остальное работает.
- Файл повреждён, под паролем, не .docx — сообщение по-русски с подсказкой («откройте в Word и сохраните как .docx»).

## 14. Проверка качества

- Разработка через тесты: каждая функция сначала получает тест.
- Правила: таблицы в `docs/rules-ru.md` и `docs/rules-kk.md` — единственный источник примеров; тесты читают их напрямую.
- Модульные тесты: модель документа и карта run (форматирование сохраняется после замены, разрезание run, гиперссылки, таблицы, колонтитулы); привязка примечаний; токенизация и деление на предложения с сокращениями; определение языка; словарь исключений; загрузчик `правила.yaml` с намеренно испорченным файлом; слияние и снятие дублей; настройки и выбор папки для записи.
- Тесты движков: клиент LanguageTool через локальную Java на Mac (`tools/dev_setup.sh` скачивает JRE и снимок в `vendor/`; тесты пропускаются, если их нет); казахский словарь на наборе из 40 юридических слов и 8 ошибок (проверен 15.09.2026: все 40 известны, все 8 помечены с верным вариантом первым); запасная русская орфография.
- Тесты окна: pytest-qt в закадровом режиме — открытие, принятие исправления, пропуск, добавление в словарь, сохранение.
- Прогон по корпусу (`tools/corpus_run.py`, только Mac): выборка 300 русских и 300 казахских актов из `~/court-analytics/corpus.db`; отчёт по каждому правилу — доля актов со срабатыванием, число срабатываний, самые частые помеченные слова. Правило, срабатывающее чаще чем в трети актов, не включается без ручного разбора; результат разбора — список отключённых правил LanguageTool и правки наших правил. Отчёт хранится в `docs/corpus-report.md` и обновляется при изменениях правил.
- Сборка лексикона (`tools/build_lexicon.py`): слова, неизвестные словарю, но встречающиеся не менее чем в 5 актах не менее чем 3 судов, проходят стеммер kazsearch (для казахского) или pymorphy3 (для русского) и ручной просмотр первых 500 по частоте; результат — `data/lexicon_kk_legal.txt`, `data/lexicon_ru_legal.txt`, `data/names_ru.txt`, `data/names_kk.txt`.
- Проверка сборки на сборщике: командная строка на образцах, сравнение числа замечаний по категориям с ожидаемым.
- Ручная приёмка по списку `docs/acceptance.md` в виртуальной Windows: открыть, проверить, принять, пропустить, добавить в словарь, сохранить копию, сохранить с примечаниями, открыть копию, запуск без Java (переименовать `java/`), запуск с защищённой от записи папки.

## 15. Этапы

0. Репозиторий, окружение на Mac (Python 3.13, JRE и LanguageTool в `vendor/`), каркас workflow, нулевая сборка `Проверка_запуска.exe`, виртуальная машина UTM.

6. Word: копия с исправлениями, примечания, именование, «Открыть в Word».
7. Поставка: спецификация PyInstaller, workflow целиком, урезка LanguageTool, инструкция, приёмка в виртуальной машине, релиз 1.0.
